# Deepen the trace-notification flow

To resolve [issue #11](https://github.com/seanpianka/tracing-layer-slack-discord/issues/11), we will replace the shallow public core configuration, factory, message, and worker interfaces in one coordinated pre-1.0 breaking release. Platform-first builders will expose only the proven extension seam: platform-specific custom renderers with a read-only Prepared Notification as their test surface. Event preparation, platform Notification Policy, HTTP adapters, retry policy, and Webhook Delivery will remain deep internal modules; no generic cross-platform layer, public delivery adapter, policy trait, callback system, or compatibility facade will be introduced. Rich and text presentation become runtime choices, delivery starts explicitly and drains on shutdown, and Discord mentions default to disabled and are sealed by the Discord adapter. This rejects PR #14's full-config leakage because message customization and webhook destination are separate responsibilities.
